<!-- Project architecture rules -->
- Keep phone lesson-goal verification in a shared deterministic module and reject incomplete or ungrounded goals before display, because truncation breaks the lesson promise.
- Keep phone source and its parallel JavaScript entry in sync, because the mobile app contains both forms.
- Unlock phone practice from credited studied stacks, falling back from a requested Course day to actual completed lessons, because catch-up progress need not match the displayed day.
- Load optional native notification bridges after the first screen mounts and contain failures, because notification setup must never block iOS launch.
- Keep the website's compact phone landing separate from the larger-screen presentation while sharing the real demo and download actions, because small screens need editorial hierarchy without duplicating behavior.
- Keep the website demo aligned with the phone’s universal three-concept AI lesson while showing preview-only rewards, because web visitors must not mistake a preview for credited app progress.
- Phone first-open order is Industry → Goal → Level → sign-up → walkthrough, with guest choices kept on-device and attached after sign-up, because new users must see their path before creating an account.
- Daily lesson cards share rendered-copy disclosure/term guards, respect optional lives, and use one XP ledger with score-based headlines, because hidden copy and unitemized rewards undermine lesson trust.
- LessonScreen owns beat transitions and the header overflow while reading-card roles share a presentation classifier, because presentation changes must not alter lesson copy or grading.
- Reading cards share opening-sentence, quote-safe list rendering and collapsible vertical spacers; retain original thin cards and source mapping until native measurement confirms a merge fits the available space, never crossing checks or the opening/rule, because denser layouts must preserve copy, scrolling and grounded grading.
- Home ring hierarchy and the displayed lesson follow credited local-day completion, using its stack ID for catch-up titles and an inline confirmation; reveal state settles across focus changes and module access stays unchanged because presentation must not add locks or overwrite progress.
- Gate Home cold-start rendering on learner/market-matched progress and XP, a successful local-day completion query (including an empty result), and the resolved lesson; retain the skeleton during CourseJourney's own lesson query, because loading flags cleared before market selection do not prove readiness.
- Dossier progress and ranks count only learner-written lines (source 'learner'); lessons never write dossier lines on their own, and legacy 'lesson' lines appear only as suggestions to rewrite, because progress must reflect the learner's own thinking.
- Select Say it prompts using shared lesson-section hints, requiring unwritten matches to reach half the strongest score and ignoring single-number-only signals; reject punctuation-only rewrites in editor and save hook, because relevance and authorship must hold beyond presentation.
- Persist dossier editor snapshots on-device scoped to learner, market, and goal; edit learner entries in place and commit only through Save or Return; Cancel and unchanged Return close without discarding drafts or refocusing, because keyboard dismissal must not silently publish learner text.
- Never drive icon-component props (e.g. vector icon colour) through Animated; crossfade static icons inside an Animated.View, because icon wrappers forward setNativeProps to a child that lacks it and crash release builds.

- Keep the learner's interview target (company, role, date) on-device per learner and market, and derive readiness, sprint/weekly plans and question track from it in one shared phone module, because Profile, Brief and the Interview Lab must agree.
- Leo speech bubbles carry one whole line of about eight words above Leo, chosen from contextual candidates rather than cut down, because long or truncated bubbles break the mascot's voice.
- Leo calls go through one server function (turn + recap) with the call type, lesson, Brief, goal, level and interview target, while the phone owns rotation, the daily limit and Brief saving, because the model must stay server-side and learner lines must be saved as the learner's own.
- Resolve displayed lesson titles and catch-up labels through the shared lesson identity helpers, because authored lessons and calendar days can differ from section names and credited study days.
- Keep quiz history scoped to learner and market on-device, key it by question content and record only displayed questions; never relax exclusion when the pool is exhausted, because shuffled IDs and aborted runs must not permit seven-day repeats.
- Goal-filter authored/generated copy and teach the takeaway before fallback checks; grounding must stay visible.
- Keep syllabus reviews additive in server prompts and phone promises; reviews must not replace angles or change day-to-topic mapping.
- Interview Lab picks its path from the saved interview target's role track (never asks Job vs School up front), and technical/behavioral tracks draw from the on-device TRACK_MOCKS bank before the question table, because technical roles must never get consulting cases or mental math.
